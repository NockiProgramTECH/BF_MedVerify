Le fil du patient

Un aller-retour, pas un formulaire.

Le patient écrit, le dispositif répond. Le fil ci-contre se met à jour à chaque simulation, avec le message réellement produit par le code Python — en ASCII, sans accents, pour tenir dans 160 caractères.

Règle des 160 caractères

Un accent force l'encodage Unicode et divise la longueur utile par deux. Les messages sont donc désaccentués côté serveur, jamais côté patient.

Priorité des verdicts

Rappel ou révocation > expiration > première vérification > même téléphone > autre téléphone. Un lot rappelé reste « rappelé », même si le code est inédit.

Sous le capot

Ce qui se passe vraiment, en quatre étapes.

La maquette reproduit le comportement de l'API FastAPI documentée dans le dépôt. Rien n'est envoyé : tout est simulé dans le navigateur.

01 · NORMALISER

Nettoyer la saisie

Majuscules, suppression des espaces, tirets et du préfixe VERIF. Une faute de frappe n'est pas une contrefaçon.

02 · HACHER

Calculer l'empreinte

HMAC-SHA256("code:" + code) et HMAC-SHA256("phone:" + numéro) avec le secret serveur.

03 · VÉRIFIER

Verrouiller et décider

Anti-spam (5/min), verrou de ligne FOR UPDATE, puis priorité rappel, expiration, première vérification.

04 · RÉPONDRE

Répondre et alerter

Message GSM-7 de 160 caractères. Trois téléphones différents sur un même code déclenchent une alerte.
